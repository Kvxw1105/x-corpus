# x-corpus

**把刷 X（推特），变成一条可复现的知识生产线。**

A human-paced, front-end-visible workflow that turns X/Twitter browsing
into a reproducible, resumable corpus pipeline — shipped as an Agent Skill.

*Agent Skill · MIT · 无需逆向 · 无需接口 · 复用你自己的登录态*

</div>

---

## 这是什么

一套经过实战验证的 **X（推特）语料采集方法论**，以 Agent Skill 形态交付。

它解决的问题：手动刷推收集资料太慢，而抓接口又太难太险（X 的 API 贵、反爬严）。
x-corpus 走中间路线——**驱动一个已登录的真实浏览器，只读页面前台可见层，按拟人节奏逐屏浏览**，
把整个过程变成可复现、可断点续跑、可审计的知识生产线。

> 首个完整验证：Muse AI 邀请码批量提取 —— 2 组关键词 → 101 条推文/评论池 →
> 4 个帖子评论区深挖 → 44 个去重邀请码（含来源链接）。全程拟人节奏，零验证码。
> 见 [cases/](cases/)。

## 为什么不是爬虫

| | 典型抓取方案 | x-corpus |
|---|---|---|
| 工作层 | 官方 API（贵/受限）/ 接口逆向 / 签名破解 | 页面前台可见层（一个正常登录用户看到的） |
| 平台视角 | 异常流量 / API 配额 | 正常用户浏览 |
| 对抗性 | 高（签名一变就崩、封 key） | 无对抗（平台改版只需微调选择器） |
| 成本 | API 计费 / 维护签名 | 零成本，复用已有登录态 |
| 边界 | 伪装成"什么都能拿" | 平台不给的就拿不到，如实记录 |

代价也如实说：速度是**人工级**的（每屏 3-6 秒），规模是**百帖级**的。要万帖规模，这个方法不适合你。

## 核心设计

```
关键词矩阵（广撒：同义词/黑话/品牌词/中英文名/组合词）
   ↓ 每词 goto 搜索页（f=live 最新）
逐滚动步累积卡片（虚拟列表必须逐步累积，不能只读当前 DOM）
   ↓ 去重累积为"搜索池"
搜索池 JSONL（断点续采，去重键=status 数字 id，任何中断零损失）
   ↓ 分桶限额筛选
正文/详情采集（逐帖 → 作者/正文/时间/互动 → 追加落盘）
   ↓
评论层/线程（主推 + 回复同一套选择器；求码/互助帖是高价值货源）
   ↓ 宽窄双模式提取（如邀请码/链接/联系方式）
成品 Markdown（去重 / 按时间倒序 / 标置信度 / 每项带来源链接）→ 知识库沉淀
```

## 安装

把 [`skill/`](skill/) 拷进你的 Agent skill 目录（如 `~/.agents/skills/x-corpus/`）。
前置条件：一个可编程的真实浏览器通道（内置浏览器 / CDP 注入均可）+ 已登录的 X 会话。

适用于 Claude Code、Codex、ZCode 或任何支持 skill/MCP + 浏览器操作的 Agent。

## 平台技巧精选（完整版见 SKILL.md 第 3-6 节）

- **直连搜索页可能渲染空白**（SPA 虚拟列表没挂载）→ `reload()` 即恢复，别傻等
- **无限滚动到底要等 5-9 秒才追加**下一批（以 `scrollHeight` 增长为准）
- **虚拟列表只保留眼前 4-6 张卡** → 必须逐滚动步累积 id，只读当前 DOM 会漏
- 滚动用 `document.documentElement.scrollTop` 赋值；`cua.scroll` 真实滚轮在 IAB 上无效
- evaluate 传参必须是 IIFE，函数字面量不会被调用
- **去重键 = status 数字 id**（永久有效，不像 token 会过期）；handle 从同一 href 白拿
- 提取类任务：先剔 URL 再抓码，宽窄双模式分置信度，每项保留来源链接可溯源

## 风控纪律（红线）

- 逐次操作间隔 2.5-3.5s 随机停顿，长任务每 10+ 次操作歇 8-15s
- **只读**：不点赞、不关注、不转发、不发推、不评论、不私信
- 出现验证码/可疑挑战 → 立即 STOPPED_SAFE，写检查点
- 用小号；遵守平台条款是使用者自己的责任

## 平台限制（如实记录，不绕过）

- 评论/回复有平台可达上限
- 转推/引用/广告会混入结果流，需按卡内特征过滤
- 登录态失效需用户重新登录（本方法不绕登录）

## 与 xhs-corpus 的关系

x-corpus 是把小红书版方法论（[xhs-corpus](https://github.com/Kvxw1105/xhs-corpus)）移植到 X 的产物。
搜索池 → 正文 → 落盘 → 沉淀的骨架一致；差异层（搜索 URL、虚拟列表滚动、追加延迟、去重键）为 X 实测。
